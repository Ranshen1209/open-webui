# Sakrylle Web Local Integration

This page summarizes only the repository-local OIDC/Sakrylle integration concerns for **Sakrylle Web**.

For protocol details, use the canonical [RP integration guide](../../sub2api/sakrylle-docs/10-platform-identity/rp-integration-guide.md). For current Sakrylle API/OIDC Provider capability, use [current-state.md](../../sub2api/sakrylle-docs/10-platform-identity/current-state.md).

## Local integration shape

Sakrylle Web uses open-webui's built-in generic Authlib OIDC provider. The provider slug is `oidc`, so the product-local routes are:

- Login start: `/oauth/oidc/login`
- Callback: `/oauth/oidc/login/callback`
- Frontend post-login landing: `/auth`
- App signout API: `/api/v1/auths/signout`

The backend OIDC substrate is intentionally generic. Sakrylle-specific behavior should normally be expressed through deployment configuration and IdP client registration, not a Sakrylle-only backend provider branch.

## Required deployment configuration

The production target is SSO-only with a Sakrylle API **confidential** client. Keep secrets out of the repository; `deploy/env.example` only documents placeholders.

Minimum required values:

- `WEBUI_URL=https://chat.sakrylle.com`
- `WEBUI_SECRET_KEY=<strong secret>`
- `OAUTH_CLIENT_ID=sakrylle-web`
- `OAUTH_CLIENT_SECRET=<confidential client secret>`
- `OPENID_PROVIDER_URL=https://sub.sakrylle.com/.well-known/openid-configuration`
- `OPENID_REDIRECT_URI=https://chat.sakrylle.com/oauth/oidc/login/callback`
- `OAUTH_PROVIDER_NAME=Sakrylle SSO`
- `OAUTH_SCOPES=openid email profile models:read chat.completions:create responses:create messages:create usage:read offline_access`
- `OPENAI_API_BASE_URLS=https://api.sakrylle.com/v1`
- `OPENAI_API_KEYS=`
- `OPENAI_API_CONFIGS={"0":{"auth_type":"system_oauth"}}`
- `OAUTH_TOKEN_ENDPOINT_AUTH_METHOD=client_secret_post`
- `OAUTH_CODE_CHALLENGE_METHOD=S256`
- `ENABLE_LOGIN_FORM=False`
- `ENABLE_SIGNUP=False`
- `ENABLE_OAUTH_SIGNUP=True`
- `OAUTH_AUTO_REDIRECT=True`
- `DEFAULT_USER_ROLE=user`

Recommended production values:

- `WEBUI_AUTH_SIGNOUT_REDIRECT_URL=https://chat.sakrylle.com/auth`
- `WEBUI_SESSION_COOKIE_SECURE=True`
- `WEBUI_AUTH_COOKIE_SECURE=True`
- `OAUTH_SESSION_TOKEN_ENCRYPTION_KEY=<strong secret>` when OAuth token encryption should be separated from `WEBUI_SECRET_KEY`
- `DATA_DIR=/app/backend/data` backed by the dedicated `sakrylle-web-data` volume in `deploy/docker-compose.sakrylle-web.yml`

Optional value:

- `OPENID_END_SESSION_ENDPOINT=https://sub.sakrylle.com/oauth/logout` only if discovery does not expose the logout endpoint or deployment wants an explicit override.

## Client registration expectations

Register the Sakrylle Web RP client in the Sakrylle API IdP with an exact redirect URI allowlist entry for:

```text
https://chat.sakrylle.com/oauth/oidc/login/callback
```

For local/staging testing, register the matching non-production callback URI instead of reusing the production redirect. Production client registration and secrets are deployment actions and require separate approval.

## Token and session storage

- The browser session is held by open-webui's existing auth cookies/session middleware.
- OAuth provider tokens are stored server-side in the `oauth_session` table.
- OAuth token payloads are encrypted before storage using `OAUTH_SESSION_TOKEN_ENCRYPTION_KEY`, falling back to `WEBUI_SECRET_KEY` when unset.
- The signout route deletes local auth cookies and the `oauth_session_id` cookie, removes the stored OAuth session row, and returns a provider logout URL when available.

## Branding integration

Sakrylle Web branding is local to this fork:

- `WEBUI_NAME` default: `Sakrylle Web`
- `APP_NAME`: `Sakrylle Web`
- HTML title: `Sakrylle Web`
- Served `/manifest.json`: generated by the backend from `WEBUI_NAME`, with Sakrylle colors and icon paths
- Static brand mount target: `/app/backend/open_webui/static/static`
- Local source asset directory: `static/brand/`

The deployed container mounts `/opt/stack/sakrylle-web/static` to `/app/backend/open_webui/static/static:ro`; keep that directory synchronized with the tracked `static/brand/` asset set.
